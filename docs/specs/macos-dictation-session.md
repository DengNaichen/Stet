# 功能规格：macOS 听写会话

**创建**：2026-11-07
**状态**：Draft
**输入**：定义 macOS 上一次听写从触发到结束的状态机、快捷键、取消、启动缓冲、录音期间的副作用，以及录音临时文件的生命周期。替代旧 spec「003 音频采集管线」中仍适用于主动听写的部分。

**范围**：macOS。iOS 的采集生命周期见[iOS 常驻麦克风与 Live Activity](ios-persistent-capture.md) spec，键盘听写见[iOS 键盘听写](ios-keyboard-dictation.md) spec。
**边界**：本 spec 拥有会话状态与转换、快捷键行为、听写与会议的互斥、取消、启动缓冲、静音 / 暂停媒体 / 提示音 / 完成通知，以及录音文件何时创建和删除。四类失败的结果矩阵见[听写结果与失败处理](dictation-outcomes.md) spec；粘贴、剪贴板兜底和“待复制”状态见[文本交付](text-delivery.md) spec；麦克风的选择与回退见[音频输入设备](audio-input-devices.md) spec；指示器外观见 [听写指示器与外观](dictation-indicator.md)；权限要求与恢复见 [权限与恢复](permissions-and-recovery.md)；引导期间的触发限制见[首次使用引导](onboarding.md) spec；会议录制本身见[会议录制与保存](meeting-recording.md) spec。
**替代**：旧 spec「003 音频采集管线」的主动听写部分。会议多轨录音不在本 spec 范围。

## 术语

- **会话**：一次从触发开始到回到空闲为止的听写。
- **录音窗口**：真正写入录音文件的时间段。采集已启动但录音窗口尚未打开时，音频只暂存在内存中。
- **启动缓冲**：录音窗口打开前暂存的最近一段音频，打开时写入文件开头。
- **听写快捷键 / 会议快捷键**：两个独立的全局快捷键，分别切换听写和会议录制。

## 用户场景与测试 *(必填)*

### 用户故事 1 - 用快捷键开始和结束听写（优先级：P1）

作为用户，我希望在任何应用里按一次快捷键开始听写，再按一次结束，文字被送回原来的应用。

**为什么是这个优先级**：这是 Stet 最核心的使用方式。

**独立测试**：在文本编辑器中按听写快捷键，确认出现指示器并开始录音；说话后再按一次，确认进入处理，最终回到空闲。

**验收场景**：

1. **Given** 会话空闲且权限齐全，**When** 我按听写快捷键，**Then** 会话进入“启动中”，指示器出现，麦克风就绪后进入“聆听”。
2. **Given** 会话处于“启动中”或“聆听”，**When** 我再按一次快捷键，**Then** 录音结束，会话进入“处理中”。
3. **Given** 会话处于“处理中”，**When** 我按快捷键，**Then** 不发生任何变化。
4. **Given** 上一次会话停在结果、错误或待复制状态，**When** 我按快捷键，**Then** 先结束上一次的状态，再开始新的会话。

---

### 用户故事 2 - 取消一次听写（优先级：P1）

作为用户，我希望说错或误触时可以取消，不产生任何文字，也不留下录音。

**为什么是这个优先级**：误触发生频繁，取消必须可靠且无副作用。

**独立测试**：分别在启动中、聆听和处理中点击指示器的取消按钮，确认没有文字被交付，指示器消失，录音文件被删除。

**验收场景**：

1. **Given** 会话处于启动中、聆听或处理中，**When** 我点击取消，**Then** 会话立即回到空闲，指示器隐藏，不交付文字。
2. **Given** 已取消，**When** 我检查临时目录，**Then** 本次录音文件已不存在。
3. **Given** 已取消，**When** 媒体此前被 Stet 暂停，**Then** 按 FR-016 恢复。

---

### 用户故事 3 - 开头的话不被吞掉（优先级：P1）

作为用户，我希望按下快捷键后马上开口，开头几个字也能被记录。

**为什么是这个优先级**：开头丢字是听写最常见、最影响信任的问题。

**独立测试**：开启提示音，按下快捷键后立即说一句话，确认转写结果包含第一个字。

**验收场景**：

1. **Given** 提示音开启，**When** 采集已启动但提示音尚未播完，**Then** 期间的音频暂存在内存，录音窗口打开时写入文件开头。
2. **Given** 暂存音频超过 1.5 秒，**When** 新音频到达，**Then** 丢弃最早的部分，只保留最近 1.5 秒。

---

### 用户故事 4 - 听写时安静的环境（优先级：P2）

作为用户，我希望听写时其他应用的声音被暂停或静音，结束后自动恢复，并通过提示音知道开始和完成。

**为什么是这个优先级**：背景声音会干扰识别；提示音是不看屏幕时唯一的反馈。

**独立测试**：开启“静音背景音频”，播放音乐后开始听写，确认音乐暂停；结束后约 1 秒确认恢复。分别开关提示音，确认开始和完成提示音。

**验收场景**：

1. **Given** “静音背景音频”开启且有媒体在播放，**When** 我开始听写，**Then** 媒体被暂停；进入聆听后其他应用的声音被静音。
2. **Given** 会话离开聆听，**When** 约 1 秒后仍未重新进入聆听，**Then** 恢复静音前的声音，并只恢复由 Stet 暂停的媒体。
3. **Given** 提示音开启，**When** 文字成功交付，**Then** 播放完成提示音；只放进剪贴板、失败或无语音时不播放。

---

### 用户故事 5 - 听写与会议互不干扰（优先级：P2）

作为用户，我希望会议录制进行中时听写不会抢占麦克风，听写进行中时会议快捷键也不会打断它。

**为什么是这个优先级**：两者共用麦克风，同时进行会损坏其中一方的录音。

**独立测试**：开始会议录制后按听写快捷键；开始听写后按会议快捷键；分别确认第二个操作没有效果。

**验收场景**：

1. **Given** 会议正在开始、录制或处理中，**When** 我按听写快捷键，**Then** 听写不开始。
2. **Given** 听写处于启动中、聆听或处理中，**When** 我按会议快捷键，**Then** 会议录制不开始。

### 边界情况

- 启动尚未完成时请求结束：记住请求，启动完成后立即结束并进入处理中。
- 录音窗口一直没有被打开（例如提示音异常）：采集就绪 1 秒后自动打开。
- 采集会话启动失败：同一设备最多尝试 4 次，每次间隔 0.15 秒；仍失败则以错误结束，结果见[听写结果与失败处理](dictation-outcomes.md) spec。
- 录音过短（不足 0.1 秒）或没有写入任何音频：删除文件，按“无语音”处理。
- 待复制状态下按快捷键：先把文字复制到剪贴板并记录历史，再开始新会话；复制失败则不开始（见[文本交付](text-delivery.md) spec）。
- 快捷键被清空：没有全局快捷键可用，只能从菜单或指示器触发。
- 会话进行中再次触发开始：忽略，不开始第二个录音。

## 需求 *(必填)*

### 功能需求

**状态机**

- **FR-001**：会话状态为：空闲、启动中、聆听、处理中、结果、待复制、错误。允许的转换为：空闲 / 结果 / 错误 / 待复制 → 启动中 → 聆听 → 处理中 → 结果 / 待复制 / 错误 / 空闲；启动中、聆听、处理中可被取消回到空闲。结果之后如何交付、何时回到空闲见[文本交付](text-delivery.md)与[听写结果与失败处理](dictation-outcomes.md) spec。
- **FR-002**：任一时刻最多一个会话在录音或处理；会话进行中的开始请求必须被忽略。
- **FR-003**：开始前必须依次满足：没有会议占用、引导允许录音、必需权限齐全。会议占用时静默忽略；后两者不满足时的表现见[首次使用引导](onboarding.md) spec 与 [权限与恢复](permissions-and-recovery.md)。
- **FR-004**：开始时必须记录当时的前台应用作为目标应用（规则见[目标应用上下文](target-app-context.md) spec），并立即显示指示器。
- **FR-005**：结束录音只能在启动中或聆听状态发生；启动中收到结束请求时，延迟到启动完成后执行。

**快捷键**

- **FR-006**：听写快捷键为“切换”模式：空闲、结果、错误、待复制时按下开始新会话；启动中或聆听时按下结束录音；处理中按下无效。当前只响应按下，不支持按住说话（待产品确认）。
- **FR-007**：快捷键必须是“修饰键 + 普通键”的组合，可在设置和引导中修改或清空。听写默认 Command + .，会议默认 Control + Option + Command + M。当前不区分左右修饰键（待产品确认）。
- **FR-008**：听写处于启动中、聆听或处理中时，会议快捷键必须无效；会议处于开始、录制或处理阶段时，听写的所有开始入口必须无效。
- **FR-009**：菜单和主界面的“开始 / 结束听写”与快捷键遵循相同的状态规则；待复制状态下界面的主操作是“Copy to Clipboard”（复制后关闭面板），不开始新会话，与快捷键不同（见[文本交付](text-delivery.md) spec）。

**取消**

- **FR-010**：启动中、聆听、处理中都必须可以取消。取消后不交付任何文字，不写入听写历史，停止采集，删除本次录音及中间文件，会话回到空闲并隐藏指示器。
- **FR-011**：当前唯一的取消入口是指示器上的取消按钮；没有取消快捷键（待产品确认）。

**启动缓冲**

- **FR-012**：采集启动后、录音窗口打开前的音频必须暂存，最多保留最近 1.5 秒；录音窗口打开时按时间顺序写入文件开头。
- **FR-013**：提示音开启时，录音窗口在开始提示音播完或 350 毫秒后（以先到者为准）打开；提示音关闭时，采集就绪后立即打开；无论哪种情况，采集就绪 1 秒后仍未打开则自动打开。

**录音期间的副作用**

- **FR-014**：“静音背景音频”（默认关闭）开启时，开始听写时若有媒体在播放则暂停，并记住是 Stet 暂停的；进入聆听后静音其他应用的系统声音。缺少系统音频录制权限时只跳过静音（见 [权限与恢复](permissions-and-recovery.md)）。
- **FR-015**：“提示音”（默认开启，音效固定为 Soft）开启时，开始时播放开始提示音；文字成功交付后播放完成提示音。只放进剪贴板、交付失败、无语音、取消时不播放完成提示音。当前设置中没有音效选择入口，音效固定为 Soft（待产品确认）。
- **FR-016**：会话离开启动中 / 聆听（进入处理中、取消或出错）1 秒后，若没有重新进入聆听，必须撤销系统静音，并且只恢复由 Stet 暂停的媒体。这 1 秒内开始新会话时取消恢复。
- **FR-017**：设置中保留“听写完成时通知”开关（默认开启；打开时会请求通知权限），但当前听写完成不发送任何系统通知（待产品确认）。

**音频电平**

- **FR-021**：录音期间必须向指示器持续提供归一化的音频电平；安静时仍保持可见的非零底值（当前采集启动时为 0.08）；录音结束、取消或出错后电平回落为 0。指示器如何使用电平见 [听写指示器与外观](dictation-indicator.md)。

**录音临时文件**

- **FR-018**：每次会话的录音写入系统临时目录中的独立文件，格式为 16 kHz、单声道、16 位线性 PCM 的 WAV，文件名不包含用户内容。
- **FR-019**：录音文件和处理过程中生成的中间文件只在本次会话处理期间存在。处理成功、失败、无语音、取消的每条路径都必须删除它们；Stet 不长期保存听写音频。
- **FR-020**：录音时长不足 0.1 秒、文件几乎为空或录音窗口打开后没有写入音频时，必须删除文件并按“无语音”交给结果处理。

### 关键实体

- **听写会话**：状态、目标应用、开始来源（快捷键 / 界面）、开始时间。
- **录音文件**：临时 WAV，归属单个会话，会话结束即删除。
- **启动缓冲**：录音窗口打开前的最近 1.5 秒音频，只在内存中。
- **副作用记录**：本次会话是否暂停了媒体、是否启用了系统静音，用于结束时精确恢复。

## 成功标准 *(必填)*

### 可衡量结果

- **SC-001**：按下快捷键后立即开口，开头第一个字出现在转写结果中的比例不低于 95%（人工抽测）。
- **SC-002**：取消后 100% 不交付文字，且临时目录中没有本次录音残留。
- **SC-003**：任何结束路径之后，临时目录中都没有本次会话的录音或中间文件。
- **SC-004**：开启“静音背景音频”时，结束后 2 秒内恢复原有播放；Stet 未暂停的媒体不会被启动。
- **SC-005**：听写与会议录制同时运行的情况为 0。

## 假设

- 听写只在用户主动触发时录音；被动监听已移除，不在本 spec 范围。
- 转写只在本机进行；远程转写、Whisper、SenseVoice 已移除。
- 处理阶段的超时、改写与回退见[改写执行](rewrite-execution.md) spec，本 spec 不规定处理时长。
- 指示器的出现位置和动画见 [听写指示器与外观](dictation-indicator.md)。

## 与当前实现的已知差异（非规范，供评审）

以下内容只记录核对基线 `b327f54` 时的代码状态，不代表产品决定。

- 全局快捷键只注册按下事件（[KeyboardShortcutsHotkeyRegistrar](../../StetMac/App/Workflows/KeyboardShortcutsHotkeyRegistrar.swift)），按键语义见 [MacDictationHotkeyInteraction](../../StetMac/App/Workflows/MacDictationHotkeyInteraction.swift)；支持按下 / 松开和左右修饰键的旧实现已在 #191 中删除，[SidedModifierFlags](../../StetMac/Core/Hotkey/SidedModifierFlags.swift) 没有调用方。
- 听写完成通知已在 `5a1e411`（#79）中移除，但 [MacDictationSettingsView](../../StetMac/Features/MacShell/HotKeySetting/MacDictationSettingsView.swift) 仍显示该开关，页脚仍写“会显示通知”；开关值只被读取到设置快照，没有使用方；打开开关时仅会请求系统通知权限（[MacDictationSettingsViewModel](../../StetMac/Features/MacShell/HotKeySetting/MacDictationSettingsViewModel.swift)）。
- 从菜单开始会议走 `toggleMeetingRecording`，不检查听写状态（[MacAppModel](../../StetMac/App/Lifecycle/MacAppModel.swift)）；只有会议快捷键经过 `handleMeetingHotkeyPressed` 的互斥检查（[MacAppSessionController+Meeting](../../StetMac/App/Workflows/MacAppSessionController+Meeting.swift)），与 FR-008 不完全一致。
- 系统静音在 macOS 26 之前没有设置静音行为（[SystemAudioMuteController](../../StetMac/Core/AudioBehavior/SystemAudioMuteController.swift) 的 `activateMuteIfNeeded` 只在 26+ 设置 `muteBehavior`），在 macOS 15 上可能只有暂停媒体生效（从代码推断，未真机核实）。
- 无法读取播放状态时，暂停媒体退化为发送一次播放 / 暂停媒体键（[MediaPlaybackController](../../StetMac/Core/Media/MediaPlaybackController.swift) 的 `pausePlaybackIfNeeded`），此时可能启动原本没有播放的媒体，与 SC-004 冲突。
- 启动缓冲与激活时机见 [MacRecordingFileSupport](../../StetMac/Core/Audio/Recording/MacRecordingFileSupport.swift)（1.5 秒上限）、[MacDictationWorkflowController](../../StetMac/App/Workflows/MacDictationWorkflowController.swift)（350 毫秒提示音期限、1 秒恢复延迟）和 [DictationViewModel](../../StetMac/Features/Dictation/DictationViewModel.swift)（1 秒自动激活），与 FR-012、FR-013、FR-016 一致。
- 临时文件由 [MacAudioCaptureService](../../StetMac/Core/Speech/MacAudioCaptureService.swift) 创建并在过短时删除；处理期间的文件由 [DictationProcessingLifetime](../../StetMac/Core/Speech/DictationProcessingLifetime.swift) 的 `DictationAudioFiles` 在所有退出路径删除，转交后台比对的文件在比对结束后删除，与 FR-019 一致。
- 取消入口只有指示器按钮（[MacDictationCapsuleSurface](../../StetMac/Features/MacShell/DictationPanel/MacDictationCapsuleSurface.swift)）；结果与待复制状态下取消按钮不响应。
