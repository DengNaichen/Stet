# 功能规格：个人词典

**创建**：2026-11-07
**状态**：Draft（待产品确认）
**输入**：按当前实现整理个人词典的词条管理、来源、iCloud 同步，以及向转写和改写提供哪些词。无可吸收的旧 spec。

**范围**：macOS 与 iOS。两端共用同一套词条数据模型；iOS 只单列平台独有的行为。
**边界**：本 spec 拥有词条的增删改与导入、启用开关、`manual` / `automatic` 来源的存储、iCloud 同步与冲突，以及“向转写 prompt、Nano hotwords、改写 preferredSpellings 提供哪些词”。自动学习怎样产生词条、以及关闭词典时停止学习，见 [修正学习](correction-learning.md)；各转写引擎怎样使用收到的词，见『转写引擎与模型准备』spec；改写提示词怎样使用这些词，见『改写执行』spec。

## 术语

- **词条**：一个正确的词或短语，不包含“原词 → 替换词”的映射。
- **来源**：`manual`（用户添加或导入）或 `automatic`（修正学习产生）。
- **启用开关**：控制词典是否参与转写、改写和自动学习的本机设置。
- **查重键**：词条经 Unicode 规范化、合并空白、去首尾空白并转小写后的形式；查重键相同视为同一词条。

## 用户场景与测试 *(必填)*

### 用户故事 1 - 添加专有名词，转写和改写都认得（优先级：P1）

作为用户，我把公司名、人名、技术术语加进词典，希望之后的转写和改写都按我写的拼法输出。

**为什么是这个优先级**：这是词典存在的原因。

**独立测试**：在 macOS 词典页添加 `Stet, FunASR`，开启改写并听写含这两个词的句子，确认改写请求和转写 prompt 中都带上这两个词条。

**验收场景**：

1. **Given** 我在输入框中输入用逗号或换行分隔的多个词，**When** 点击添加，**Then** 每段各成为一个手动词条，空段被忽略。
2. **Given** 词典中已有 `Python`，**When** 我再添加 `python`，**Then** 不产生重复词条。
3. **Given** 词典已启用，**When** 开始一次听写，**Then** 本次转写与改写使用的词条与 FR-010～FR-013 一致。

---

### 用户故事 2 - 在多台设备上看到同样的词典（优先级：P1）

作为用户，我在一台 Mac 上加的词，希望在我的另一台设备上也能用。

**为什么是这个优先级**：词典是长期积累的个人数据，丢失或分叉代价高。

**独立测试**：两台登录同一 iCloud 账户的设备，在一台上添加、删除、清空，确认另一台在系统同步后列表随之更新。

**验收场景**：

1. **Given** 两台设备使用同一 iCloud 账户和同一个 iCloud 键值存储，**When** 一台添加词条，**Then** 另一台收到同步通知后刷新列表。
2. **Given** 一台设备清空词典，**When** 另一台收到同步，**Then** 另一台也为空，不会用本地旧缓存“复活”词条。
3. **Given** 云端没有任何词典数据（从未同步），**When** 读取词典，**Then** 使用本机缓存。

---

### 用户故事 3 - 批量导入与整理（优先级：P2，macOS）

作为用户，我有一份现成的术语表，希望一次导入；也希望能编辑、删除或清空词条。

**为什么是这个优先级**：方便维护，但不影响词典的基本作用。

**独立测试**：导入一份含重复项的文本文件，确认提示“新增 N、跳过 M”；编辑一个自动词条，确认其变为手动来源；清空时需要输入 CLEAR 确认。

**验收场景**：

1. **Given** 一个不超过 512 KB 的 UTF-8 或 UTF-16 文本 / CSV 文件，**When** 导入，**Then** 按逗号和换行拆分，新增不重复的词条并报告跳过的重复数。
2. **Given** 导入后词典总量会超过同步上限（FR-008），**When** 导入，**Then** 拒绝导入并说明原因，词典不变。
3. **Given** 我编辑一个词条，**When** 保存，**Then** 原词条被替换为新内容，结果为手动来源。
4. **Given** 我点击清空，**When** 输入 CLEAR 并确认，**Then** 所有词条与来源信息被删除并同步。

---

### 用户故事 4 - 临时关闭词典（优先级：P3，macOS）

作为用户，我怀疑词典干扰了识别，希望先关掉它而不删除词条。

**独立测试**：关闭开关后听写，确认转写 prompt 和改写请求都不带词条，词条列表保留。

**验收场景**：

1. **Given** 启用开关关闭，**When** 听写，**Then** 不向转写或改写提供任何词条，也不自动学习。
2. **Given** 启用开关关闭，**When** 我重新打开，**Then** 原有词条全部恢复参与。

### 边界情况

- 词条只含空白：忽略。
- 词条内部有连续空白或换行：合并为单个空格。
- 手动添加一个已存在的自动词条：提升为手动来源并采用手动拼写；自动学习不会把手动词条降为自动。
- 来源元数据缺失或无法识别：按手动处理。
- 云端词条与来源元数据分批到达：先按手动显示，元数据到达后刷新。
- 导入文件为空、无法解码或超过 512 KB：拒绝并说明原因。
- 两台设备离线期间各自修改：以 iCloud 键值存储最后写入的完整列表为准，另一台的修改可能丢失（待产品确认）。
- macOS 首次升级到当前版本：旧版本保存在本机的词典在新词典为空时迁移一次。

## 需求 *(必填)*

### 功能需求

**词条管理**

- **FR-001**：词条必须按查重键去重；保留最先出现的拼写，但手动来源覆盖自动来源时采用手动拼写。
- **FR-002**：添加、导入时按英文逗号和换行拆分输入；拆分后为空的片段忽略。
- **FR-003**：新词条追加在列表末尾；词条顺序在同步和重新读取后保持不变。
- **FR-004**：删除按查重键匹配；清空必须同时删除词条和来源信息。
- **FR-005**：macOS 支持添加、编辑、删除、导入和需要输入 CLEAR 确认的清空；编辑后的词条为手动来源。
- **FR-006**：iOS 主 App 支持添加和删除；不提供编辑、导入、清空、启用开关和来源图标。（待产品确认）
- **FR-007**：导入只接受不超过 512,000 字节的 UTF-8 或 UTF-16 文本，忽略 BOM；结果报告新增数和跳过的重复数（跳过数只统计与已有词条重复的项；文件内部的重复项在拆分时已合并，不计入）。
- **FR-008**：导入后词条与来源的编码总量不得超过 800,000 字节；超过时拒绝整次导入。手动添加当前不检查该上限。（待产品确认）

**来源**

- **FR-009**：每个词条必须带 `manual` 或 `automatic` 来源。macOS 词典页用人物 / 星光图标区分来源。来源的存储与兼容规则如下（从原修正学习 spec 迁入，含义不变）：
  - `dictionary.entries` 继续保存字符串数组；`dictionary.entries.provenance.v1` 保存按实际拼写索引的来源。来源缺失 / 未知时按 `manual` 处理。
  - 删除与清空同时更新来源元数据；明确的空云端数组按删除处理，不回退复活旧缓存。
  - 旧版客户端可以继续读取词条，但不能标注新的来源行为。云端文本 / 元数据分批抵达时，缺失的来源暂按手动展示，元数据通知到达后刷新。

**向转写和改写提供哪些词（本 spec 拥有）**

- **FR-010**：启用开关关闭时，向转写 prompt、Nano hotwords 和改写 preferredSpellings 提供的词条均为空。
- **FR-011**：改写 preferredSpellings：提供全部词条（手动与自动），不设数量上限，按列表顺序；macOS 与 iOS 相同，与选用哪个改写服务无关。
- **FR-012**：Fun-ASR Nano hotwords：先排列全部手动词条，再排列自动词条；依次选入，跳过会使逗号拼接后的总长度超过 400 个字符的词条，最多选 50 个。
- **FR-013**：其他 macOS 本地引擎的转写 prompt：Parakeet（FluidAudio）提供全部词条的逗号拼接；Apple Speech 提供与 FR-012 相同的选择结果，以便运行时回退到 Nano 时仍有热词。各引擎是否、怎样使用，见『转写引擎与模型准备』spec。
- **FR-014**：iOS 的转写不使用词典；iOS 只把词条提供给改写。
- **FR-015**：会议转写不使用词典。（当前行为）

**启用开关**

- **FR-016**：启用开关默认开启，只保存在本机，不随 iCloud 同步。
- **FR-017**：关闭开关不删除任何词条；关闭时停止自动学习的规则见 [修正学习](correction-learning.md) FR-009。

**iCloud 同步与冲突**

- **FR-018**：词条列表和来源信息必须同时写入本机缓存和 iCloud 键值存储；每次修改后都写入整份列表。
- **FR-019**：读取时云端存在词条数组（包括空数组）就以云端为准并刷新本机缓存；云端不存在时使用本机缓存。明确的空云端数组按删除处理。
- **FR-020**：收到 iCloud 外部变更通知且涉及词典键时，用云端整份列表替换本机缓存，并通知界面刷新。
- **FR-021**：冲突以 iCloud 键值存储最后写入的整份列表为准，不做逐条合并。（待产品确认）
- **FR-022**：同步范围由应用的 iCloud 键值存储标识决定；当前 macOS 与 iOS 使用各自的标识。（待产品确认：是否要求 Mac 与 iPhone 之间同步。）

**数据去向**

- **FR-023**：词条会出现在发给用户选定改写服务的请求中，也会交给本机转写引擎；除此之外只经 iCloud 键值存储同步，不发送到其他服务。

### 关键实体

- **词条**：拼写（规范化后）与来源。
- **词条列表**：有序、按查重键去重的词条集合；本机缓存键 `dictionary.entries`，来源键 `dictionary.entries.provenance.v1`。
- **启用开关**：本机设置 `dictionary.enabled`，默认开启。
- **导入结果**：新增数、跳过数。

## 成功标准 *(必填)*

### 可衡量结果

- **SC-001**：添加、删除、清空在同一 iCloud 键值存储的设备间同步后结果一致；清空后被旧缓存复活的词条数为 0。
- **SC-002**：词典关闭时，转写 prompt 与改写请求中出现的词条数为 0。
- **SC-003**：Nano hotwords 任何时候不超过 50 个词条、400 个字符，且手动词条优先。
- **SC-004**：查重键相同的词条在列表中最多出现一次。

## 假设

- iCloud 键值存储的系统总容量约 1 MB；800,000 字节的导入上限为此预留余量。
- iCloud 未登录或不可用时，词典仅在本机工作。
- iOS 键盘扩展不读取词典。

## 待产品确认

1. **Mac 与 iPhone 是否共享词典**：当前两端使用各自 Bundle ID 派生的 iCloud 键值存储标识，只在同平台设备间同步（FR-022）；Debug 构建也使用独立标识。可选方向：两端改用同一标识以共享；保持分平台。
2. **冲突策略**：当前整份列表后写覆盖（FR-021），离线并发修改会丢失一方。可选方向：保持；改为按词条合并（需定义删除的表示）。
3. **容量上限**：手动添加不检查 800,000 字节上限（FR-008），超出系统容量时同步会失败且无提示。可选方向：所有写入统一检查上限；保持。
4. **iOS 管理能力**：iOS 没有启用开关、编辑、导入、清空和来源显示（FR-006）。可选方向：补齐；保持精简。
5. **改写词条无上限**：改写会收到全部词条（FR-011），大词典会显著加长改写请求。可选方向：保持；设上限或按相关性筛选。

## 与当前实现的已知差异（非规范，供评审）

以下只记录核对基线 `b327f54` 的代码状态，不代表产品决定。

- iCloud 键值存储标识为 `$(TeamIdentifierPrefix)$(CFBundleIdentifier)`（[macOS entitlements](../../StetMac/Stet.entitlements)、[iOS entitlements](../../StetMobile/StetMobile/StetMobile.entitlements)），两端 Bundle ID 不同，因此不会互相同步（待产品确认 1）。
- 冲突处理是整份覆盖：[DictionaryModel](../../Packages/StetEngine/Sources/StetCore/DictionaryModel.swift) 的 `updateRecords` 每次写整份数组，外部变更通知时整份替换本机缓存。
- 手动添加（`addEntries`）不检查 `maximumStoredUTF8ByteCount`，只有 `importEntries` 检查。
- Parakeet 收到全部词条的 prompt，但 [FluidAudioTranscriptionService](../../StetMac/Core/FluidAudio/FluidAudioTranscriptionService.swift) 的 `transcribe` 没有使用 prompt 参数；Apple Speech 同样忽略 prompt。词条选择见 [DictationPipelineFactory](../../StetMac/Core/DictationPipeline/DictationPipelineFactory.swift) 的 `makeTranscriptionPrompt` 和 [FunASRNanoHotwordPrompt](../../Packages/StetEngine/Sources/StetCore/FunASRNanoHotwordPrompt.swift)。
- iOS 只在改写中使用词条（[TranscriptPostProcessor](../../StetMobile/StetMobile/Core/Dictation/TranscriptPostProcessor.swift)）；iOS 词典页（[DictionaryViewModel](../../StetMobile/StetMobile/Features/Dictionary/ViewModels/DictionaryViewModel.swift)）只有添加和删除，启用开关在 iOS 上始终为默认开启。
- macOS 编辑词条（[DictionaryViewModel](../../StetMac/Features/MacShell/Dictionary/DictionaryViewModel.swift) 的 `saveEntries`）先替换再按手动重新添加，因此编辑后的自动词条变为手动来源。
- 旧版本词典的一次性迁移见 [LegacyDictionaryMigration](../../StetMac/Shared/Models/LegacyDictionaryMigration.swift)：只在新词典为空时导入。
