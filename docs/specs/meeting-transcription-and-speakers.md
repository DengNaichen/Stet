# 功能规格：会议转写与说话人

**创建**：2026-11-07
**状态**：Draft
**输入**：定义会议录制结束后的处理：转写、可选的说话人分离、本地声纹档案、无法识别说话人的归类，以及转写文档格式。吸收 旧 spec「009 被动监听 / 声纹门控」 中仍适用于会议的说话人身份要求。

**范围**：macOS。
**边界**：本 spec 从“会议音频已落盘”开始，到转写文档和说话人数写入为止。录制、文件位置和会话状态见「会议录制与保存」spec；转写模型和说话人模型的下载、镜像与存储见「转写引擎与模型准备」spec；个人词典向转写提供哪些词见「个人词典」spec；对外读取转写见「MCP 对外契约」spec。
**替代**：替代 009 被动监听 spec 中的说话人档案与身份标注部分。被动监听本身（全天监听、待定缓冲、主人参与开门、热键后恢复被动）已移除，不在范围内。

## 术语

- **说话人分离**：把会议音频切成按说话人区分的片段，每个片段带一个匿名轨道编号。
- **声纹档案**：从用户录制的参考语音得到的聚合声纹，只存在本机 Keychain。分为“本人”和“已知说话人”两类。
- **重叠片段**：分离结果中多人同时说话的片段。
- **转写文档**：会话目录中的 `transcript.md`。

## 用户场景与测试 *(必填)*

### 用户故事 1 - 录完会议自动得到转写文档（优先级：P1）

作为用户，我停止会议录制后，希望 Stet 自动在本机转写，并在会话目录里生成一份可读的文档。

**为什么是这个优先级**：转写是会议录制的主要产出。

**独立测试**：关闭说话人分离，录制一段 2 分钟的双人对话并停止，确认会话目录出现转写文档、会话状态变为完成。

**验收场景**：

1. **Given** 说话人分离关闭，**When** 录制停止且音频保存成功，**Then** Stet 在本机转写混音，所有文字归在“Speaker 1”名下，写入转写文档，会话状态为完成。
2. **Given** 录音中没有可识别的语音，**When** 处理完成，**Then** 文档写明“本次录音没有识别到语音”，会话状态仍为完成。
3. **Given** 处理过程中出错，**When** 处理结束，**Then** 文档写明处理失败的原因和“录音已保存”，会话状态为失败，录制状态保持“已录制”。

---

### 用户故事 2 - 可选地区分不同说话人（优先级：P1）

作为用户，我开启“分离说话人”后，希望转写文档按说话人分段，并能认出我自己和我登记过的人。

**为什么是这个优先级**：多人会议没有说话人信息时，文档很难使用。

**独立测试**：已登记本人声纹，开启分离，录一段本人与另一个未登记的人交替发言的会议，确认文档中本人段落标为“Me”，另一人标为“Speaker N”。

**验收场景**：

1. **Given** 分离已开启且模型就绪，**When** 处理会议，**Then** 文档按说话人分段，每段标注说话人和起止时间。
2. **Given** 某轨道的声音与本人档案匹配，**When** 生成文档，**Then** 该轨道全部段落标为“Me”；与某个已知说话人档案匹配时，标为该档案的名字。
3. **Given** 某轨道不匹配任何档案或识别失败，**When** 生成文档，**Then** 该轨道标为“Speaker N”（N 为轨道序号），不被强行归到最接近的档案。
4. **Given** 某片段是多人重叠或没有轨道，**When** 生成文档，**Then** 该片段标为“Unresolved”，重叠片段附“overlapping”标记。

---

### 用户故事 3 - 开启分离前明确下载模型（优先级：P2）

作为用户，我希望开启分离时被告知需要下载约 241 MB 的模型，并能在下载完成前照常录制普通会议。

**为什么是这个优先级**：大体积下载必须由用户确认；模型缺失不能阻止录制。

**独立测试**：在模型缺失时打开开关，确认弹出下载确认；下载中开始录制，确认按不分离处理。

**验收场景**：

1. **Given** 模型未下载，**When** 我打开“分离说话人”，**Then** Stet 询问是否下载约 241 MB 模型；选“暂不”时开关保持关闭。
2. **Given** 我确认下载，**When** 下载并校验完成，**Then** 开关自动打开；下载中开关保持关闭，可以取消下载。
3. **Given** 分离已开启但开始录制前模型校验失败，**When** 我开始会议录制，**Then** Stet 提供三个选择：下载并修复（本次不开始录制）、本次不分离直接录制（不改变保存的偏好）、取消。

---

### 用户故事 4 - 管理本机声纹档案（优先级：P3）

作为用户，我希望登记自己和最多三位已获同意的人的声纹，并能随时删除。

**独立测试**：登记一个本人档案和一个已知说话人档案，确认需要三段有效语音、已知说话人需勾选同意；删除后该人在后续会议中按未知处理。

**验收场景**：

1. **Given** 我登记已知说话人，**When** 未勾选“我已获得录制并登记此人的许可”，**Then** 不能开始录制参考语音。
2. **Given** 一段参考语音的有效语音不足 1.2 秒，**When** 提交，**Then** 该段被拒绝并提示原因，已收集的其他段保留。
3. **Given** 三段参考语音都有效，**When** 最后一段完成，**Then** 生成档案；每段原始录音在提取声纹后立即删除。
4. **Given** 我删除某个档案，**When** 之后处理会议，**Then** 该人的声音按未知说话人处理。

### 边界情况

- 处理阶段 Stet 被退出：处理中断，不自动续跑（见「会议录制与保存」spec 待确认项）。
- 单个转写窗口失败：该窗口文字视为空并跳过，其他窗口继续；整场不因单窗口失败而失败。
- 说话人分离本身失败：整场处理失败，按用户故事 1 场景 3 处理。
- 分离结果为空（未检测到说话人片段）：退回不分离的处理方式。
- 声纹模型版本变化：已有档案标为“需要重新登记”，不再参与匹配，直到重新登记。
- 会议设置在录制中被修改：只影响下一场会议。

## 需求 *(必填)*

### 功能需求

**处理流程**

- **FR-001**：处理阶段必须在全部音频文件收尾后开始，输入为混音。
- **FR-002**：转写必须在本机完成，使用 Fun-ASR Nano，与听写选择的引擎无关；不传语言提示，也不传个人词典热词。（固定引擎、不使用词典是否为产品意图，待产品确认）
- **FR-003**：处理阶段对外显示三个子阶段：准备转写、分离说话人（仅分离开启时）、转写。
- **FR-004**：说话人分离关闭时，混音按最长 20 秒切成窗口逐段转写，所有非空文字标为“Speaker 1”。
- **FR-005**：说话人分离开启时，先对整场混音做分离，再按以下规则生成转写片段：裁掉超出音频范围的部分；每个片段最长 20 秒，超长则切分；同一轨道、都不重叠、间隔不超过 0.30 秒的相邻片段合并，合并后仍不超过 20 秒。
- **FR-006**：单个窗口转写失败时视为空文本跳过；用户取消以外的转写错误不得使整场处理失败。（静默跳过是否需要在文档中注明，待产品确认）
- **FR-007**：分离失败、转写模型不可用或音频无法读取时，整场处理失败：转写文档写入失败说明且注明录音已保存，会话状态记为失败，录制状态不变。
- **FR-008**：处理成功后，会话记录的说话人数为处理结果中不同说话人标签的个数（含“Unresolved”，也含因文字为空而未写入文档的片段所带的标签）。

**说话人身份**

- **FR-009**：说话人身份只在分离开启时识别。每个轨道只识别一次，使用该轨道第一个非重叠片段，结果用于该轨道的全部片段。该片段语音不足 1.2 秒时，整条轨道按未知处理，不再用后续片段重试。（只用第一个片段是否为产品意图，待产品确认）
- **FR-010**：标签规则：
  - 与本人档案匹配 → “Me”；
  - 与已知说话人档案匹配 → 档案名；
  - 不匹配、置信不足或识别出错的非重叠轨道 → “Speaker N”（N 为轨道序号加 1）；（无法识别的说话人归为“其他人”是否认可，待产品确认）
  - 重叠片段或没有轨道的片段 → “Unresolved”。
- **FR-011**：匹配必须是开集判断：只有相似度达到档案阈值、且领先第二名至少 0.08 时才算匹配；否则按未知处理，不得强行归到最接近的档案。新档案的默认阈值为 0.60。
- **FR-012**：只使用状态为“可用”的档案参与匹配。

**声纹档案**

- **FR-013**：最多 1 个本人档案和 3 个已知说话人档案，总数不超过 4。
- **FR-014**：档案只保存名字、角色、声纹模型标识、归一化的聚合声纹、参考段数、阈值和时间戳，不保存任何音频；存于本机 Keychain，不同步到 iCloud，仅本设备、首次解锁后可读。
- **FR-015**：登记需要 3 段参考语音，每段至少含 1.2 秒有效语音；每段录音在提取声纹后立即删除；三段必须来自同一声纹模型。
- **FR-016**：登记已知说话人前必须确认已获本人同意；登记本人不需要。
- **FR-017**：声纹模型变化，或档案使用旧的未校准阈值（0.70）时，档案必须标为“需要重新登记”，并在档案列表中显示。
- **FR-018**：删除档案必须立即从 Keychain 移除其声纹；删除最后一个档案时移除整个 Keychain 项。

**分离开关**

- **FR-019**：“分离说话人”默认关闭，偏好跨启动保留；修改只影响下一场会议。
- **FR-020**：打开开关时若模型未就绪，必须先征得下载确认（约 241 MB，一次性）；下载与校验期间开关保持关闭且不可操作，完成后自动打开；下载中可通过“取消下载”取消。下载失败时显示原因并提供“重试下载并开启”。
- **FR-021**：开始录制前，若开关开启，必须重新校验模型；校验失败时按用户故事 3 场景 3 让用户选择，不自动下载，也不静默修改偏好。

**转写文档格式**

- **FR-022**：转写文档为 Markdown，依次包含：
  - 标题：关联预期会议的标题；没有标题或为占位标题“(No title)”时用“Meeting · 开始时间”；
  - `Started`、`Ended`、`Duration`（“Ns”或“M min Ns”）；
  - 关联预期会议时追加 `Scheduled`（计划起止）、`Attendees`（参会人名）、`Meeting`（会议链接），各自有值才写；
  - 处理失败时的说明段；
  - 正文：每段为“**标签** (m:ss–m:ss[ · overlapping])”，下一行为文字；同一说话人连续的非重叠段落合并为一段，以换行连接；空文字段不写入；
  - 没有任何文字时写“No speech was recognized in this recording.”。
- **FR-023**：文档中的固定字段和标签（“Me”“Speaker N”“Unresolved”等）当前为英文，不随界面语言变化。（是否需要本地化，待产品确认）

### 关键实体

- **说话人片段**：起止样本、轨道编号（可空）、是否重叠、活动置信度。
- **转写片段**：起止时间、说话人标签、文字、是否重叠。
- **声纹档案**：ID、名字、角色（本人 / 已知说话人）、声纹模型标识、聚合声纹、参考段数、阈值、状态（可用 / 需要重新登记）。
- **分离设置**：是否开启、模型状态（缺失 / 检查中 / 下载中 / 校验中 / 就绪 / 失败）。

## 成功标准 *(必填)*

### 可衡量结果

- **SC-001**：录音成功保存的会议中，100% 生成转写文档（成功或含失败说明）。
- **SC-002**：分离开启、本人已登记时，本人发言段落中至少 90% 标为“Me”（参照 009 SC-011 的 90% 目标，需重新测量）。
- **SC-003**：未登记说话人的段落 0 次被标为某个已登记档案名（低于阈值时）。
- **SC-004**：分离关闭的会议处理中，0 次加载说话人分离或声纹模型。

## 假设

- 转写模型由「转写引擎与模型准备」spec 负责下载；会议处理不负责触发 Fun-ASR Nano 下载。
- 说话人分离运行在混音上，不分别处理麦克风轨和系统音频轨。
- 声纹识别只判断声音相似度，不做活体检测。
- 被动监听已移除；旧听写记录中的被动来源标记只为兼容旧数据保留，由「听写历史与统计」spec 负责。

## 待产品确认

1. **无法识别说话人的归类**（index 待决项）：当前非重叠轨道识别不出时标为“Speaker N”，只有重叠或无轨道片段标为“Unresolved”；旧 009 要求不确定区域保持 unresolved。可选：认可现状；低置信轨道也标 Unresolved。
2. **被动监听去留**（index 待决项）：本 spec 按“已移除”写；若只是暂时下线，需要另立 spec。
3. **声纹档案管理入口**：登记和删除界面目前不可达，已有档案仍参与匹配但用户看不到也删不掉。可选：恢复入口（放在会议设置页）；移除声纹功能并清除已有档案；维持隐藏并停止使用已有档案。
4. **转写引擎与词典**：会议固定用 Fun-ASR Nano，不用词典。可选：跟随听写引擎；固定 Nano 但加入词典热词；维持现状。
5. **单窗口转写失败的呈现**：当前静默跳过，整场仍为完成。可选：在文档中标注缺失时段；失败比例过高时判失败。
6. **文档语言**：固定英文。可选：随界面语言；维持英文以便 agent 稳定解析。
7. **轨道身份只看第一个片段**：当前每条轨道只用第一个非重叠片段识别一次，片段过短即整条轨道判为未知。可选：选最长或累积多段语音再识别；维持现状。
8. **声纹模型隐式下载**：分离开启且本机没有声纹模型时，处理阶段会自动联网下载，没有确认。可选：并入分离模型的下载确认；维持现状。
