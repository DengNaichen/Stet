# 功能规格：听写历史与统计

**创建**：2026-11-07
**状态**：Draft（待产品确认）
**输入**：定义每次听写在本机留下哪些记录、记录中各段文本的含义、用户怎样查看 / 导出 / 删除记录，以及概览页统计数字的计算口径。

**范围**：macOS。iOS 当前不保存听写历史，也没有统计页。
**边界**：本 spec 拥有历史记录的字段与状态、`finalText` 的含义、旧被动监听记录的兼容、历史的查看 / 搜索 / 导出 / 删除与保留期，以及概览、热力图、按应用统计的口径。目标应用怎样确定见[目标应用上下文](target-app-context.md) spec；粘贴、剪贴板兜底和“待复制”状态见[文本交付](text-delivery.md) spec；转写与改写文本怎样产生见[转写引擎与模型准备](transcription-engines.md)和[改写执行](rewrite-execution.md) spec；会议转写不进入听写历史，见[会议转写与说话人](meeting-transcription-and-speakers.md) spec。

## 术语

- **历史记录**：一次产生非空转写的听写在本机保存的一条记录。
- **原始转写**：转写引擎的输出（经常规规整），未经改写。
- **改写文本**：改写服务处理后的文本；本次没有改写时为空。
- **交付文本（`finalText`）**：Stet 确认已经交给用户的文本，见 FR-004。
- **统计会话**：概览页统计使用的一条独立记录，只含开始时间、时长、字数和目标应用，不含文本。
- **字数**：统计口径下的“说话单位”，见 FR-014。

## 用户场景与测试 *(必填)*

### 用户故事 1 - 找回说过的话（优先级：P1）

作为用户，当粘贴没有成功或我想找回之前的一段话时，我希望在历史页看到每次听写的原始转写和改写结果。

**为什么是这个优先级**：交付失败时历史是找回文本的最后途径；没有它用户会丢失口述内容。

**独立测试**：完成几次听写（含一次改写、一次粘贴失败），打开历史页，确认每次都有记录、按时间倒序显示，粘贴失败的那次也在。

**验收场景**：

1. **Given** 一次听写得到非空转写，**When** 转写与改写完成，**Then** 在交付开始前就保存一条历史记录，之后无论交付成功、失败还是被打断，记录都保留。
2. **Given** 本次启用了改写，**When** 我查看这条记录，**Then** 同时看到原始转写和改写文本，两者有区分标记。
3. **Given** 本次转写为空或在处理中被取消，**When** 我查看历史，**Then** 没有新增记录。
4. **Given** 历史页已打开，**When** 我回到 Stet 或点击刷新，**Then** 列表重新加载，显示最新记录。

---

### 用户故事 2 - 搜索、导出和清空历史（优先级：P2）

作为用户，我希望能搜索历史、把历史导出为文件，并在需要时一次性清空。

**为什么是这个优先级**：历史只存在本机；导出和清空是用户掌控自己数据的基本手段。

**独立测试**：输入关键词确认过滤结果；导出 JSON 并检查字段；清空后确认历史页为空且无法撤销。

**验收场景**：

1. **Given** 历史中有多条记录，**When** 我输入关键词，**Then** 只显示原始转写、改写文本、目标应用名称或 Bundle ID 中包含该词（不区分大小写）的记录。
2. **Given** 历史非空，**When** 我选择导出，**Then** Stet 让我选择保存位置，保存的 JSON 包含 FR-002 列出的全部字段，不包含任何声纹数据。
3. **Given** 历史非空，**When** 我选择清空并确认，**Then** 所有历史记录被永久删除；取消确认时不删除任何记录。

---

### 用户故事 3 - 看到自己用了多少听写（优先级：P2）

作为用户，我希望在概览页看到总听写时长、字数、节省的时间、平均语速，过去一年每天的活跃度，以及在哪些应用里用得最多。

**为什么是这个优先级**：统计帮助用户感知价值，但不影响听写本身。

**独立测试**：在两个应用中各完成若干次听写，打开概览页，核对四个数字、热力图当天格子和按应用排行与 FR-013 到 FR-018 的口径一致。

**验收场景**：

1. **Given** 我完成了一次 10 秒、说了 20 个字的听写，**When** 打开概览页，**Then** 总时长、字数、节省时间和平均语速按 FR-015 计算并更新。
2. **Given** 我今天有听写，**When** 查看热力图，**Then** 今天的格子按今天的字数着色，悬停或点击显示当天字数和节省时间。
3. **Given** 我在超过 6 个应用里用过听写，**When** 查看按应用统计，**Then** 显示字数最多的 6 个应用，其余合并为“Other”。
4. **Given** 从未有带目标应用的听写，**When** 查看按应用统计，**Then** 显示“下次听写后开始统计”的空状态。

---

### 用户故事 4 - 旧记录升级后仍可读（优先级：P3）

作为老用户，我希望升级后以前的历史（包括被动监听时期的记录）依然能看、能导出。

**独立测试**：用含旧版存储（包括被动来源记录）的环境启动新版本，确认记录可读、可导出，旧存储文件未被删除。

**验收场景**：

1. **Given** 旧版本把历史存在旧位置，**When** 新版本首次启动，**Then** 历史被完整复制到新的独立存储，所有文本阶段保留，旧文件保持不变。
2. **Given** 存在被动监听时期的记录，**When** 我查看或导出，**Then** 它们和普通记录一样显示，导出中保留来源、起止时间和说话人片段。

### 边界情况

- 历史存储无法打开：历史页显示“无法加载历史”的错误，不显示为空列表。
- 写入失败：只记录日志，不打断听写，也不提示用户。
- Nano 的无热词对照转写（FR-003）晚于交付完成才返回：仍补写到同一条记录；下一次听写开始时，仍在后台运行的对照转写被取消、其结果被丢弃，不串到下一条。
- 交付停在“待复制”时用户直接退出 Stet：记录保持“处理中”，`finalText` 为空。
- 首次引导中的练习听写（目标可能是 Stet 自身）同样写入历史和统计（待产品确认）。
- 听写时长不足 1 秒：写入历史，但不写入统计（待产品确认）。
- 文本中的日文假名、西里尔字母等不计入字数（FR-014）。

## 需求 *(必填)*

### 历史记录

- **FR-001**：每次得到非空转写的听写，必须在转写与改写全部完成后、交付开始前保存一条历史记录。转写为空、录音被取消或处理中被取消时不保存。
- **FR-002**：每条历史记录保存：唯一标识、时间、原始转写、改写文本（无改写时为空）、交付文本、目标应用的 Bundle ID 与名称、交付状态、来源（主动 / 被动）、录音起止时间、处理状态与失败码、说话人片段、无热词对照转写。当前新记录只写入前八项和对照转写，其余字段为旧记录兼容保留。
- **FR-003**：使用 FunASR Nano 引擎时，Stet 在后台用空热词提示对同一段音频再转写一次，结果作为“无热词对照转写”附加到同一条记录；它不显示在历史页，只出现在导出中（待产品确认）。
- **FR-004**：`finalText` 的含义：Stet 确认已经交给用户的那段文本。只在以下情况写入，同时写入目标应用和状态：
  - 粘贴已验证成功，或按[文本交付](text-delivery.md) spec 判定为乐观完成：状态“已完成”。
  - 设置为只复制到剪贴板且复制成功：状态“已完成”（当前 macOS 听写固定走自动粘贴，此分支暂无入口）。
  - 粘贴失败后退回剪贴板，且“待复制”状态被用户确认、自动收起或被下一次听写接替：状态“待复制”，`finalText` 为留在剪贴板中的文本。
  其他情况（交付失败且剪贴板写入失败、交付中被取消、停在“待复制”时退出）下 `finalText` 保持为空，状态保持“处理中”（待产品确认）。
- **FR-005**：`finalText` 一经写入不再改变。用户在目标应用中对已粘贴文本的后续修改、发送与否都不回写 `finalText`；修正观察见[修正学习](correction-learning.md) spec。
- **FR-006**：交付状态取值及含义：处理中（已保存，交付未确认）、已完成、待复制、未交付。“未交付”只出现在被动监听时期的旧记录中，当前流程不再写入。
- **FR-007**：历史写入不得阻塞录音、转写或交付；写入按提交顺序串行执行，写入失败只记日志。

### 查看、搜索、导出与删除

- **FR-008**：历史页按时间倒序显示最近 300 条记录。每条显示日期、目标应用名称、原始转写，以及（有改写时）改写文本；改写文本以强调样式区分。文本可选中复制。说话人片段和对照转写不在历史页显示。
- **FR-009**：搜索在已加载的记录中按用户故事 2 场景 1 列出的字段做不区分大小写的包含匹配；交付文本不参与搜索（待产品确认）。
- **FR-010**：导出为 JSON（时间为 ISO 8601），由用户选择保存位置，默认文件名 `stet-history.json`。导出内容为当前已加载的全部记录（最多 300 条，不受搜索过滤影响），字段见 FR-002；不得包含声纹向量等生物特征数据。
- **FR-011**：删除只有“全部清空”一种方式，必须二次确认并提示不可撤销；不支持删除单条（待产品确认）。
- **FR-012**：历史没有自动过期，记录永久保存在本机直到用户清空（待产品确认）。清空历史不影响统计（见 FR-019）。

### 统计口径

- **FR-013**：每次得到非空最终文本、且录音时长不少于 1 秒的听写，在交付开始前写入一条统计会话；交付是否成功不影响统计（待产品确认）。统计会话独立于历史保存。
- **FR-014**：字数按“说话单位”计算：每个汉字或韩文音节计 1；每段连续的 ASCII 字母、数字和撇号计 1；空白和标点不计；其他文字（如假名、西里尔字母、带重音的拉丁字母本身）不计。计数对象是最终文本（有改写时为改写后文本）。
- **FR-015**：时长为从开始录音的触发到停止录音的触发之间的墙钟时间。概览页四个数字：
  - 总听写时长：全部统计会话时长之和。
  - 字数：全部统计会话字数之和，超过 1,000 以 K、超过 1,000,000 以 M 表示。
  - 节省时间：max(0, 字数 ÷ 40 × 60 秒 − 总时长)，即与每分钟打 40 字相比；页面底部注明这一假设。
  - 平均语速：字数 ÷ 总时长（分钟），取整；没有数据时显示“—”。
- **FR-016**：热力图覆盖包括今天在内的最近 365 天，按本地日历日（以统计会话开始时间归日）汇总字数，5 档着色；一周起始日跟随系统设置。每格提示当天字数和当天节省时间。
- **FR-017**：按应用统计：有 Bundle ID 的按 Bundle ID 归组，否则按应用名称归组；两者都没有的会话不计入此列表。按字数降序，字数相同按次数降序，再按名称排序；最多显示 6 个，其余合并为“Other”。占比按字数计算，所有应用字数为 0 时按次数计算。每项显示名称、字数和次数。
- **FR-018**：概览页在出现时和 Stet 回到前台时重新计算。
- **FR-019**：统计没有删除入口，也不随清空历史而清空（待产品确认）。

### 存储与兼容

- **FR-020**：历史与统计各自使用独立的本机存储，位于 Application Support 下按 Bundle ID 分隔的目录，不经 iCloud 同步，不上传。
- **FR-021**：首次启动新版本时，若新历史存储不存在而旧的共享存储中有历史数据，必须把旧数据完整复制到新存储（包括全部文本阶段），且不修改、不删除旧文件。
- **FR-022**：缺少新字段的旧记录按“主动来源、处理已完成、开始时间等于记录时间”读取。
- **FR-023**：被动监听时期的记录（来源为被动）必须保持可读、可显示、可导出，包括录音起止时间、处理状态和说话人片段；被动监听本身已移除，不再产生此类记录。
- **FR-024**：字数口径曾经变更。升级到当前口径时执行一次重算：用历史文本（优先交付文本，其次改写文本，再次原始转写）按 FR-014 重算，与结束时间相差 3 秒以内的统计会话按最近者匹配；匹配不到的会话保留原字数。重算只执行一次。

### 关键实体

- **历史记录**：见 FR-002。
- **说话人片段**：旧被动记录中的一段文字及其起止时间、说话人身份（自己、已知某人、其他人、未识别）、相似度和是否重叠。
- **统计会话**：开始时间、时长、字数、目标应用 Bundle ID 与名称。
- **概览汇总**：会话数、总时长、总字数及由此派生的节省时间和平均语速。

## 成功标准 *(必填)*

- **SC-001**：所有得到非空转写的听写 100% 出现在历史中，包括交付失败的那些。
- **SC-002**：交付成功（含乐观完成和只复制）的记录 100% 有 `finalText`；交付未确认的记录 `finalText` 为空。
- **SC-003**：导出文件可被标准 JSON 解析器读取，且不含任何声纹向量。
- **SC-004**：给定一组已知统计会话，概览四个数字、热力图和按应用排行与 FR-014 到 FR-017 的手工计算完全一致。
- **SC-005**：升级后旧历史（含被动记录）100% 可读，旧存储文件未被修改。

## 假设

- 被动监听已移除，不在本 spec 范围内；只保留其旧记录的兼容。
- 历史与统计只在本机，不设云同步；隐私边界遵循 index 的通用原则。
- 统计的目标应用与历史的目标应用来自同一次“本次目标应用”快照。

## 待产品确认

1. **保留期与删除方式**（对应 index“听写历史与会议音频的保留期限与删除方式”）：当前永久保留，只能全部清空，没有单条删除。可选：增加单条删除；设置保留期（如 30 / 90 天）；保持现状。
2. **交付未确认的记录**：交付失败、取消或停在“待复制”时退出，记录永远停在“处理中”。可选：新增“交付失败”状态；沿用“未交付”；保持现状但在界面上标出。
3. **清空历史是否同时清空统计**：当前不清空，统计也没有删除入口。可选：清空历史时一并清空；单独提供“重置统计”；保持现状。
4. **统计计入范围**：当前交付失败的听写也计入，不足 1 秒的不计入，引导中的练习也计入。可选：只统计交付成功的；去掉 1 秒门槛；排除引导练习。
5. **字数口径覆盖的文字**：假名、西里尔字母等不计数。可选：按 Unicode 词边界计数；保持“汉字 + 拉丁词”口径。
6. **搜索与导出范围**：搜索不含交付文本；导出和列表只覆盖最近 300 条。可选：搜索纳入交付文本；导出全部历史。
7. **无热词对照转写**：每次 Nano 听写都额外跑一次后台转写，结果只在导出里可见，像是诊断用途。可选：保留为默认；改为开发者开关；移除。
8. **iOS 历史**：iOS 当前不保存任何听写历史。可选：iOS 也保存；明确 iOS 不做历史。

## 与当前实现的已知差异（非规范，供评审）

以下只记录 2026-11-07（基线 `b327f54`）核对时的代码状态，不代表产品决定。

- 规范正文按当前行为撰写，主要差异集中在“待产品确认”项；下列是需要特别注意的实现细节。
- “未交付”状态在当前代码中没有任何写入方，只在旧被动记录的测试中出现（[HistoryEntry](../../Packages/StetEngine/Sources/StetCore/HistoryEntry.swift) 的 `HistoryEntryStatus`；[DictationHistoryServiceTests](../../Packages/StetEngine/Tests/StetCoreTests/DictationHistoryServiceTests.swift) 的 `legacyPassiveHistoryRemainsReadableAndExportable`）。
- `finalText` 只在 [MacDictationCaptureCoordinator](../../StetMac/App/Workflows/MacDictationCaptureCoordinator.swift) 的三处“History point C”和 [MacDictationWorkflowController](../../StetMac/App/Workflows/MacDictationWorkflowController.swift) 的 `finalizePendingResultHistory` 写入；粘贴失败后的剪贴板兜底要等“待复制”结束（[MacAppSessionController+Dictation](../../StetMac/App/Workflows/MacAppSessionController+Dictation.swift) 的 `resolvePendingResult`）才定稿。
- 历史在交付前提交（[DictationViewModel](../../StetMac/Features/Dictation/DictationViewModel.swift) 的 `commitPending` 调用处）；统计同样在交付前写入（[MacDictationWorkflowController](../../StetMac/App/Workflows/MacDictationWorkflowController.swift) 的 `handleCompletedResult`），1 秒门槛在 `stopActiveCapture`。
- 统计会话的开始时间是在处理完成时用“当前时间 − 时长”倒推的，不是真实开始时间；处理耗时越长偏差越大，跨午夜时可能归到错误的一天（`handleCompletedResult` 中的 `record(startedAt:)`）。
- 搜索字段不含 `finalText`，导出使用已加载的 `entries` 而非搜索结果，加载上限 300（[MacHistorySettingsView](../../StetMac/Features/MacShell/Setting/MacHistorySettingsView.swift) 的 `filtered`、`exportJSON`；[DictationHistoryService](../../Packages/StetEngine/Sources/StetCore/DictationHistoryService.swift) 的 `fetchRecent`）。
- 历史页日期只显示月 / 日，不显示年份和时间（`HistoryEntryRow`）。
- 清空历史只删除历史存储（`deleteAll`），统计存储在 [DictationStatsModel](../../StetMac/Shared/Models/DictationStatsModel.swift) 中独立保存，没有删除接口。
- 无热词对照转写在引擎为 Nano 时默认开启（[DictationPipelineFactory](../../StetMac/Core/DictationPipeline/DictationPipelineFactory.swift) 的 `recordsNoHotwordTranscript`），由 [ConfigurableSpeechService](../../StetMac/Core/Speech/ConfigurableSpeechService.swift) 后台执行。
- 字数口径与一次性重算见 [DictationWordCounter](../../StetMac/Shared/Utilities/DictationWordCounter.swift) 与 [DictationWordCountMigration](../../StetMac/Shared/Models/DictationWordCountMigration.swift)；重算只能匹配最近 10,000 条历史。
- iOS 代码中没有任何历史或统计的存储与界面（StetMobile 目录下无 `HistoryEntry` 引用）。
- 目标应用的 Bundle ID 与名称不在 `commitPending` 时写入，而是和 `finalText` 一起在交付确认时写入（`DictationHistoryService.updateFinal`）；因此交付未确认的记录没有目标应用，历史页不显示应用名，按应用名搜索也匹配不到。
- 当前 macOS 听写的 `CaptureSettings` 固定为 `shouldCopyToClipboard: false`、`shouldAutoPaste: true`（[MacDictationWorkflowController](../../StetMac/App/Workflows/MacDictationWorkflowController.swift) 的 `captureSettings`），“只复制到剪贴板”的直接完成分支在实际流程中不会触发。
