# 功能规格：修正学习

**创建**：2026-11-07（在原有“从修改中学习词典”文档基础上改写为完整模板）
**状态**：Draft（原文状态为 active，规则经用户批准；本次只补全模板结构）
**输入**：原 correction-learning.md 中的目标、用户可见行为、观察边界、实现入口、验证和明确限制全部保留。

**范围**：macOS 自动粘贴；词典数据模型由 macOS / iOS 共享。iOS 不做修正学习。
**边界**：本 spec 拥有观察窗口、差分提取、跳过条件，以及“关闭个人词典时停止自动学习”。词条的存储、来源标记的持久化、iCloud 同步、以及词典向转写和改写提供哪些词，见[个人词典](personal-dictionary.md) spec。粘贴本身见[文本交付](text-delivery.md) spec；`finalText` 的含义见[听写历史与统计](dictation-history-and-stats.md) spec；辅助功能缺失时静默跳过见 [权限与恢复](permissions-and-recovery.md)。

## 术语

- **插入区域**：按粘贴前输入框的前后文本定位出的、本次粘贴的文本所在范围。
- **观察窗口**：粘贴后 Stet 只读观察插入区域的一段时间。
- **自动词条**：由修正学习加入词典、来源为 `automatic` 的词条；手动加入的为 `manual`。

## 用户场景与测试 *(必填)*

### 用户故事 1 - 改正一次，以后自动认得（优先级：P1）

作为用户，我把 Stet 粘贴进来的 `拍图` 改成 `Python` 后，希望 Stet 记住 `Python`，下次直接写对。

**为什么是这个优先级**：这是本功能的全部价值。

**独立测试**：在可读取的文本框中听写，粘贴后把一个词改掉并停顿 1 秒，确认词典出现带星光图标的 `Python`。

**验收场景**：

1. **Given** 粘贴结果已确认出现在输入框，**When** 我把 `拍图` 改为 `Python` 并停顿约 1 秒，**Then** 词典新增自动词条 `Python`。
2. **Given** 同上，**When** 我把 `Pyton` 改为 `Python`，**Then** 同样学习完整的 `Python`。
3. **Given** 同上，**When** 我把 `明天` 改为 `后天`、或把 `3` 改为 `4`，**Then** 也学习，不判断修改意图。
4. **Given** 同上，**When** 我改完后按 Return / Enter / Tab，**Then** 立即做一次最终采样并学习。

---

### 用户故事 2 - 不学无意义的修改（优先级：P1）

作为用户，我只是在后面补一句、删掉几个字、或改了标点，不希望词典被塞进垃圾词条。

**为什么是这个优先级**：词条质量直接影响转写与改写。

**独立测试**：分别做纯追加、纯删除、只改标点 / 空白 / emoji，确认词典不变。

**验收场景**：

1. **Given** 已确认插入，**When** 我只在插入文本后追加或只删除部分内容，**Then** 不创建词条。
2. **Given** 已确认插入，**When** 我只改标点、空白或 emoji，**Then** 不创建词条。
3. **Given** 已确认插入，**When** 我只改大小写（`python` → `Python`），**Then** 学习 `Python`。

---

### 用户故事 3 - 我手动加的词不被自动学习改坏（优先级：P2）

作为用户，我手动加过的词条，不希望被自动学习改成别的来源或拼写。

**为什么是这个优先级**：手动词条代表用户的明确意图。

**独立测试**：先手动添加 `Python`，再通过修正学到 `python`，确认词条仍为手动来源和原拼写；反过来先学到自动词条，再手动添加，确认提升为手动。

**验收场景**：

1. **Given** 已有手动词条，**When** 自动学到同一词，**Then** 不覆盖手动来源。
2. **Given** 已有自动词条，**When** 我手动添加同一词，**Then** 提升为手动来源并采用手动拼写。
3. **Given** 词典页列表，**When** 我查看词条，**Then** 用人物 / 星光图标和提示区分手动与自动。

---

### 用户故事 4 - 关闭词典即停止学习（优先级：P2）

**为什么是这个优先级**：用户关闭词典时，不应在背后继续读取输入框。

**独立测试**：关闭个人词典后听写并修改，确认不建立观察、词典不变；观察中途关闭，确认观察结束。

**验收场景**：

1. **Given** 个人词典已关闭，**When** 粘贴完成，**Then** 不建立观察。
2. **Given** 观察进行中，**When** 我关闭个人词典，**Then** 下一次采样即结束观察，不再加入词条。

### 边界情况

- 粘贴后 2 秒内输入框没有出现预期结果：不学习。
- 目标应用或输入框改变、窗口外文本改变、超过 30 秒、开始下一次听写、程序化替换、取消输出：结束本次观察。
- 读不到完整值、选区或可靠元素：跳过学习，不影响输出流程。
- 安全输入框（密码框）：不观察。
- 仅复制到剪贴板（未发出粘贴）：不建立观察。
- 同一观察窗口内区域又稳定为另一个不同内容：再按相对原插入文本的差分学习一次，先前学到的词条不撤回。
- 读取暂时失败（非最终采样）：继续等待，不用旧值代替；最终采样时读取失败则结束且不学习。

## 需求 *(必填)*

### 功能需求

**目标**

- **FR-001**：用户修改 Stet 粘贴到目标输入框的内容后，自动把替换结果加入个人词典。
- **FR-002**：不判断修改意图，不判断是不是专有名词或识别错误，也不按相似度或修改比例过滤。
- **FR-003**：词典保存正确的词或短语，不创建全局的“原词 → 替换词”强制替换规则。

**学习规则**

- **FR-004**：`拍图 → Python`、`Pyton → Python` 都学习完整的 `Python`；`明天 → 后天`、`3 → 4` 也学习；独立的纯追加和纯删除跳过。
- **FR-005**：大小写修改可以学习；纯标点、空白、emoji 不创建词条。
- **FR-006**：每个词条记录 `manual` 或 `automatic` 来源；词典页用人物 / 星光图标和提示区分。
- **FR-007**：现有词条无来源时按手动添加处理；自动学习不覆盖已有手动来源；手动添加同一自动词条会提升为手动来源并采用手动拼写。
- **FR-008**：自动词条即时复用现有转写 prompt、Nano hotwords 和改写 preferredSpellings 链路；具体提供哪些词见[个人词典](personal-dictionary.md) spec。
- **FR-009**：关闭个人词典也停止自动学习：关闭时不建立新观察，进行中的观察在下一次采样时结束，且不再写入自动词条。（本 spec 拥有此规则。）
- **FR-010**：没有新增撤销提示、批准步骤或意图分类。

**观察边界**

- **FR-011**：在 Stet 自己的粘贴键事件之前，捕获目标应用、同一辅助功能输入框、原值和 UTF-16 选区；目标必须是当时的前台应用且不是 Stet，输入框必须是文本框、文本区域或组合框。
- **FR-012**：先确认预期插入结果实际出现在该输入框中（最多等待 2 秒），再观察修改。
- **FR-013**：观察窗口最长 30 秒，间隔约 200 ms，修改稳定约 1 秒后提取；Return / Enter / Tab（不含按住 Shift）可触发一次最终采样。这些按键只用于触发采样，不记录按键字符。
- **FR-014**：这些按键不是消息已发送的证明，因此不改写历史记录中 `finalText` 的含义（见[听写历史与统计](dictation-history-and-stats.md) spec）。
- **FR-015**：始终按粘贴前的前后文本定位本次插入区域。窗口外改动、目标应用 / 输入框改变、超限、下一次听写、程序化替换或取消输出会结束旧观察。
- **FR-016**：读不到完整值、选区或可靠元素时跳过学习，不影响原有输出流程；仅复制到剪贴板不建立观察。
- **FR-017**：安全输入框不观察。缺少辅助功能授权时静默跳过（见 [权限与恢复](permissions-and-recovery.md)）。
- **FR-018**：当前大小限制：粘贴前原值不超过 64,000 个 UTF-16 单位，插入文本不超过 32,000 个 Unicode 标量，观察中的输入框不超过 96,000 个 UTF-16 单位；超限即不学习或结束观察。每次读取输入框的等待上限约 0.1 秒。

**数据去向**

- **FR-019**：原始快照只留在内存，不写日志、不发送给新服务。观察只读取粘贴前捕获的那个输入框，不做全局文本 / 按键记录，观察期间不读剪贴板，不向输入框写入。
- **FR-020**：词典沿用已有 iCloud 同步和用户选定转写 / 改写服务的 prompt 行为。

**来源持久化**

- **FR-021**：来源的存储格式、缺失时按 `manual` 处理、删除与清空、旧客户端兼容和云端分批抵达的规则由[个人词典](personal-dictionary.md) spec 负责（其 FR-009），本 spec 不另行定义。

### 关键实体

- **修正观察**：粘贴前的前缀、后缀、插入文本、开始时间、是否已确认插入、当前候选区域、最近一次变化时间、已学到的内容；只在内存中。
- **文本修正**：一对“原文片段 → 替换片段”，只有替换片段写入词典。
- **词条来源**：`manual` 或 `automatic`。

## 成功标准 *(必填)*

### 可衡量结果

- **SC-001**：Python 与 Swift 共用的 108 个差分样例和 14 个来源样例全部一致通过。
- **SC-002**：纯追加、纯删除、纯标点 / 空白 / emoji 修改产生的词条数为 0。
- **SC-003**：无法确认插入、无法唯一定位、或目标切换的情况下，错误学习次数为 0（宁可不学习）。
- **SC-004**：关闭个人词典后，新增自动词条数为 0。

## 假设

- 只观察编辑后的快照，不识别输入意图或 IME 提交状态。
- 学到的词条交给[个人词典](personal-dictionary.md) spec 管理，其 iCloud 同步和服务提供规则不因来源不同而改变。

## 明确的限制

- 两个文本快照无法区分相邻的多词替换和“替换后立即追加”：`old → Python today` 会学整个连续短语。
- 只观察编辑后的快照，不识别输入意图或 IME 提交状态；输入法组合过程在某些应用中也可能暴露为文本变化。
- 系统中文分词器通过当前全部样例，但不保证所有生僻人名和 jieba 的边界完全一致；后续真实反例继续补入共用样例。
- 无确认的插入、多处重复导致无法定位的文本，以及切换目标时错过的最后修改，宁可不学习。

## 待产品确认

1. **可观察的输入框类型**：当前只观察文本框、文本区域和组合框（FR-011），网页内可编辑区域等其他角色不学习，Chrome、Electron 类应用中的修正大多学不到。可选方向：保持；扩大到可编辑网页区域并补充样例。
2. **同一窗口多次学习**：区域先稳定为 B、再改成 C 时，B 和 C 都会成为词条（见边界情况）。可选方向：保持；窗口结束时只保留最后一次结果。
