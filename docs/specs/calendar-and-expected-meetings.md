# 功能规格：日历与预期会议

**创建**：2026-11-07
**状态**：Draft
**输入**：定义 macOS Stet 如何从用户选择的日历同步即将到来的会议，形成“预期会议”，在会前提醒，并从提醒直接开始录制。

**范围**：macOS。
**边界**：本 spec 负责日历开关与选择、同步窗口与时机、日历事件到预期会议的映射、预期会议状态、会前提醒及其操作。日历与通知权限的要求与恢复见 [权限与恢复](permissions-and-recovery.md)；录制本身见「会议录制与保存」spec；预期会议标题、参会人等写入转写文档的格式见「会议转写与说话人」spec；通过 MCP 读取预期会议、读写日历的工具契约见「MCP 对外契约」spec。
**替代**：无。

## 术语

- **日历会议**：会议设置页中的“日历会议”开关，打开后才同步。
- **所选日历**：用户在 Stet 中勾选的日历；同步和 MCP 日历工具都只作用于它们。
- **预期会议**：由日历事件映射而来、Stet 本地保存的一条即将进行的会议，带稳定的 Stet ID 和状态。
- **同步窗口**：每次同步覆盖的时间范围：当天 0 点到当前时间之后 14 天。

## 用户场景与测试 *(必填)*

### 用户故事 1 - 会前收到提醒并一键开始录制（优先级：P1）

作为用户，我希望日历里的会议开始前 5 分钟收到 Stet 通知，点一下就开始会议录制，录音自动带上会议标题和参会人。

**为什么是这个优先级**：这是日历集成存在的主要原因，减少忘记录制。

**独立测试**：在所选日历中建一个 10 分钟后开始的会议，确认 5 分钟前收到通知；点“开始录制”，确认录制开始，转写文档标题为该会议标题。

**验收场景**：

1. **Given** 日历会议已开启且所选日历中有一场未来会议，**When** 距开始还有 5 分钟，**Then** Stet 发送通知，标题为会议标题（无标题时为“会议即将开始”），正文为开始时间和参会人。
2. **Given** 收到提醒，**When** 我点“开始录制”或点通知本身，**Then** 开始会议录制，并把该预期会议的标题、计划时间、参会人、会议链接写入录制记录；预期会议状态变为“录制中”。
3. **Given** 收到提醒，**When** 我点“跳过”，**Then** 预期会议状态变为“已跳过”，之后的同步不会把它改回待开始。
4. **Given** 会议已结束或状态不是待开始，**When** 我点旧通知的“开始录制”，**Then** 不开始录制。

---

### 用户故事 2 - 只同步我选的日历（优先级：P1）

作为用户，我希望只有我勾选的日历进入 Stet，其他日历（例如家庭、订阅日历）不被读取。

**为什么是这个优先级**：日历内容敏感，范围必须由用户控制。

**独立测试**：只勾选“工作”日历，确认只有该日历的会议产生提醒；取消勾选后，其未来会议的提醒被撤销。

**验收场景**：

1. **Given** 首次开启日历会议并授权，**When** 打开会议设置页，**Then** 列出全部日历，默认都不勾选。
2. **Given** 我勾选或取消某个日历，**When** 选择变化，**Then** 立即重新同步；取消勾选的日历中待开始的预期会议变为“已取消”，提醒撤销。

---

### 用户故事 3 - 日历变化自动跟上（优先级：P2）

作为用户，当会议在日历里被改期、取消或我拒绝了邀请，我希望 Stet 的提醒随之更新。

**独立测试**：把已同步的会议改期、再删除，确认提醒时间随之变化、最终被撤销。

**验收场景**：

1. **Given** 已同步的会议在日历中被改期，**When** 日历数据库变化，**Then** Stet 重新同步，提醒按新时间重排，预期会议 ID 不变。
2. **Given** 会议在日历中被删除、取消或被我拒绝，**When** 同步，**Then** 该预期会议变为“已取消”，提醒撤销。
3. **Given** 某预期会议已在录制或已完成，**When** 日历中该事件被修改，**Then** 更新时间和标题等信息，但保留“录制中 / 已完成”状态。

---

### 用户故事 4 - 关闭或失去权限时干净撤销（优先级：P3）

**独立测试**：关闭日历会议，或在系统设置中撤销日历权限，确认窗口内所有待开始提醒被撤销。

**验收场景**：

1. **Given** 日历会议已开启，**When** 我关闭开关，**Then** 停止同步，窗口内待开始的预期会议全部变为“已取消”，所选日历保留。
2. **Given** 日历权限被撤销，**When** 下一次同步，**Then** 同样撤销，状态显示“需要日历权限”。

### 边界情况

- 全天事件、已取消事件、结束时间不晚于开始时间的事件：不映射为预期会议。
- 占位标题（“(no title)”“(no subject)”“no title”“untitled event”，不分大小写）：视为无标题。
- 会议开始前不足 5 分钟才同步到：约 1 秒后立即提醒。
- 同步进行中又触发同步：合并为再同步一次，不并发执行。
- 提醒触发录制时会议正在录制或处理：不开始录制。
- 从提醒开始录制失败（例如权限不足）：预期会议保持“待开始”。

## 需求 *(必填)*

### 功能需求

**开关与选择**

- **FR-001**：“日历会议”默认关闭。打开时请求日历完全访问权限；用户拒绝时开关保持关闭。权限要求见 [权限与恢复](permissions-and-recovery.md)。
- **FR-002**：只有开关打开且已获得完全访问权限时，设置页才列出日历供勾选；默认不勾选任何日历。（默认不选是否合适，待产品确认）
- **FR-003**：所选日历在关闭开关后仍保留，重新打开时沿用。所选日历同时限定 MCP 日历工具的范围，见「MCP 对外契约」spec。
- **FR-004**：设置页显示同步状态：关闭、需要日历权限、就绪、同步中、已是最新、同步失败。

**同步**

- **FR-005**：同步窗口为当天 0 点到当前时间之后 14 天，只读取所选日历中的事件。
- **FR-006**：以下时机必须触发同步：开关打开、开关已开时应用启动、所选日历变化、日历数据库变化、每隔 1 小时、Mac 从睡眠唤醒。同一时刻最多一个同步在执行，期间的新触发合并为结束后再同步一次。
- **FR-007**：开关关闭或权限丢失时，停止所有同步触发，并把窗口内待开始的预期会议标为“已取消”。

**映射**

- **FR-008**：以下事件不映射：全天事件、已取消事件、结束不晚于开始的事件、当前用户已拒绝的事件。
- **FR-009**：每个事件映射为一条预期会议，字段包括：来源（日历账户与日历）、事件的稳定 ID、计划起止时间、标题（去除首尾空白，占位标题置空）、参会人（排除当前用户；用姓名，无姓名时用邮箱）、会议链接、备注、事件修改时间。
- **FR-010**：会议链接取事件 URL（仅 http/https）；没有时，从地点和备注中找第一个已知会议服务链接（zoom.us、teams.microsoft.com、meet.google.com、webex.com、feishu.cn、larksuite.com、whereby.com、around.co 及其子域名）。

**预期会议状态**

- **FR-011**：预期会议状态为：待开始、录制中、已跳过、已取消、已完成。同一来源与事件 ID 始终对应同一个 Stet ID。
- **FR-012**：同步合并规则：
  - 新事件 → 新建，状态待开始；
  - 已有事件 → 更新字段；原状态为录制中或已完成时保留原状态；原状态为已跳过时保持已跳过；
  - 窗口内待开始、但本次同步中已不存在的事件 → 已取消（不删除记录）。
- **FR-013**：从提醒开始录制成功后，预期会议变为“录制中”，并记录对应的会议会话 ID；该会话处理结束（成功或失败）后变为“已完成”。
- **FR-014**：用户跳过 → 已跳过，撤销提醒。
- **FR-015**：预期会议保存在 `~/Library/Application Support/Stet/expected-meetings.json`，只在本机。当前不清理过期记录。（保留期限待产品确认）

**提醒**

- **FR-016**：对每个“待开始且尚未结束”的预期会议，在计划开始前 5 分钟发送一次通知；该时刻已过则约 1 秒后发送。预期会议变化时先撤销旧提醒再重排；应用启动时重新排定。
- **FR-017**：通知标题为会议标题，无标题时为“会议即将开始”；正文为“开始于 时间”，有参会人时附“与 姓名列表”。
- **FR-018**：通知提供“开始录制”和“跳过”两个操作；点通知本身等同“开始录制”。（点通知本身是否应直接开始录制，待产品确认）
- **FR-019**：“开始录制”只在预期会议仍为待开始、尚未结束、且当前没有会议在开始/录制/处理时生效；开始流程（含说话人分离预检、权限与听写互斥）按「会议录制与保存」spec 执行。
- **FR-020**：预期会议变为录制中、已跳过、已取消时，撤销其待发和已送达的提醒。通知权限缺失时静默跳过，不影响同步。

### 关键实体

- **所选日历**：日历 ID 集合，本机偏好保存。
- **预期会议**：Stet ID、来源、事件 ID、计划起止、标题、参会人、会议链接、备注、来源修改时间、状态、关联的会议会话 ID。
- **同步状态**：关闭、需要权限、就绪、同步中、已是最新（含时间）、失败（含原因）。
- **会前提醒**：每个预期会议至多一条待发通知，以预期会议 ID 标识。

## 成功标准 *(必填)*

### 可衡量结果

- **SC-001**：所选日历中的未来非全天会议，100% 在开始前约 5 分钟收到提醒（通知权限已允许时）。
- **SC-002**：日历中改期或删除的会议，在下一次触发同步后 100% 更新或撤销提醒。
- **SC-003**：未勾选日历中的事件 0 次出现在预期会议中。
- **SC-004**：从提醒开始录制的会议，100% 在转写文档中带有会议标题与参会人。

## 假设

- 日历数据来自系统日历（EventKit），Stet 不直接连接 Google、Exchange 等服务。
- 预期会议目前只由日历同步产生；agent 通过 MCP 在所选日历中创建的事件，经下一次同步后成为预期会议。旧的“agent 直接同步预期会议”工具已于 `e30dfe8` 移除。

## 待产品确认

1. **点通知本身直接开始录制**：当前点通知正文与点“开始录制”相同。可选：点正文只打开 Stet；维持现状。
2. **录制中途失败时的预期会议状态**：当前只有从处理阶段结束才标“已完成”；录制中途失败（例如睡眠）不经过处理阶段，预期会议停在“录制中”。可选：失败也标已完成；新增“失败”状态；回到待开始。
3. **过期预期会议**：已结束但从未开始录制的会议一直是“待开始”，文件也不清理。可选：结束后标为“已错过”；定期清理超过某期限的记录。
4. **默认所选日历**：当前默认一个都不选，开启后若不勾选则什么也不同步。可选：默认选中系统默认日历；默认全选；维持现状。
5. **agent 是否可直接创建预期会议**：当前只能通过在所选日历中建事件间接创建。可选：恢复直接写入预期会议的 MCP 工具；维持现状。

## 与当前实现的已知差异（非规范，供评审）

以下内容只记录 2026-11-07（`b327f54`）核对时的代码状态，不代表产品决定。

- 录制中途失败时预期会议停在“录制中”：只有从处理子阶段转到空闲或失败才标已完成。证据：[MacMeetingWorkflowController](../../StetMac/App/Workflows/MacMeetingWorkflowController.swift) 的 `receive`。
- 从提醒开始录制不检查听写状态和权限门槛（已在「会议录制与保存」spec 记录）。证据：同上 `startExpectedMeeting`。
- 从提醒开始录制后若录制中途失败，`activeExpectedMeetingID` 不会清除；之后另一场会议处理结束（成功或失败）时，会把这条旧的预期会议标为“已完成”。证据：同上 `receive`、`startExpectedMeeting`。
- 同步用 EventKit 按时间范围取事件，返回的是与窗口有重叠的事件；而预期会议同步要求事件开始时间落在窗口内，否则整次同步报错。因此跨越当天 0 点的事件（例如昨晚开始、今天凌晨结束）按代码推断会使整次同步失败，未实测。证据：[LiveEventKitClient](../../StetMac/Core/Calendar/LiveEventKitClient.swift) 的 `events(matching:)`、[ExpectedMeetingCoordinator](../../StetMac/Core/Meetings/ExpectedMeetingCoordinator.swift) 的 `sync`。
- 打开开关时用户拒绝日历权限，开关保持关闭，但同步控制器仍被启动并把状态置为“需要日历权限”，于是关闭状态下显示“需要日历权限”。证据：[MacAppModel](../../StetMac/App/Lifecycle/MacAppModel.swift) 的 `setCalendarMeetingsEnabled`。
- 同步窗口、触发时机、映射与合并规则与 FR-005 至 FR-012 一致。证据：[CalendarSyncController](../../StetMac/Core/Calendar/CalendarSyncController.swift)、[CalendarMeetingMapper](../../StetMac/Core/Calendar/CalendarMeetingMapper.swift)、[ExpectedMeetingCoordinator](../../StetMac/Core/Meetings/ExpectedMeetingCoordinator.swift)。
- 提醒时间、文案与操作与 FR-016 至 FR-018 一致。证据：[MacDictationCompletionNotificationService](../../StetMac/Core/Notifications/MacDictationCompletionNotificationService.swift) 的 `scheduleExpectedMeeting`。
- 设置页的日历列表与选择。证据：[MacCalendarMeetingSettingsView](../../StetMac/Features/MacShell/MeetingSetting/MacCalendarMeetingSettingsView.swift)、[SelectedCalendarStore](../../StetMac/Core/Calendar/SelectedCalendarStore.swift)。
