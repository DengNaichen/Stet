# 会议说话人分段性能

2026-09-17：macOS 会议录音处理使用 FluidAudio `efficientV2_1` 配置。
实时被动监听仍使用默认低延迟配置。FluidAudio 固定到已验证的提交
`0a58e26875ba4df7615cca7d48406b6b93144265`（包含上游 #728），不追踪 main。

## 本地对照

M4、32 GiB、macOS 26.6.2，Release 构建，31 分 21 秒的 16 kHz 单声道录音。
测试直接加载 analyzer 并调用 `addAcceptedAudio` / `finalizeAcceptedAudio`；
不加载或运行 ASR。以下是同一依赖版本、不同配置的两轮顺序实测，不是严格的旧版/新版对照。

| 配置 | 第一轮推理 | 第二轮推理 | 第二轮模型加载 |
|---|---:|---:|---:|
| default | 96.90 秒 | 98.86 秒 | 0.241 秒 |
| efficientV2_1 | 30.87 秒 | 29.74 秒 | 0.226 秒 |

高效配置推理约快 3.1–3.3 倍。其进程 physical footprint 峰值约 575–594 MiB，
包含完整音频数组和测试进程；每秒采样，且顺序测试可能保留分配器缓存，不代表模型独占内存。
第一次高效模型准备耗时 126.44 秒，包含下载和 Core ML 编译，不计入推理时间。
缓存可复用，但切换模型或清除缓存后可能再次下载。

两种配置分别跨两轮产生完全相同的输出，但配置之间的边界和标签存在差异。
80 ms 网格上，两者都判为单人说话的区间标签一致率为 90.78%；
这不是准确率，尚无人工标注质量验收。上述数据只代表一个样本，不构成普遍性能承诺。
原始音频、转录与逐段输出不入库。
